# Strokera 立项书（2026-09）

## 问题与定位

函数作画证明数学表达式可以成为创作材料，但专业绘画还需要前后层次、笔触方向、局部修改、材质与可见的创作过程。Strokera 的目标不是把提示词直接变成成图，而是定义一份人和 Agent 都能写、审、改的绘画过程协议，并通过 CLI 执行。

## 用户与场景

1. 画家：先定构图和层次，让 Agent 提议曲线或笔触，再逐层校正。
2. 创意编程者：将参数曲线与手工路径混用，输出可重放的作品。
3. Agent 开发者：通过稳定 JSON 输入、JSON 结果与退出码进行工具调用。
4. 教学者：用屏幕回放观察一幅画如何建立，而不只看成品。

## 产品边界

核心是 SPP 文档和 CLI。屏幕 UI 在首期是只读预览与回放；编辑器、压力感应笔刷、物理颜料、AI 规划和参考图转笔触属于后续阶段。首期不承诺专业绘画软件的完整替代，也不宣称自动规划模块已经可用。

## 架构

`SPP JSON → validator → deterministic geometry sampler → SVG renderer → browser preview`。Agent 通过 CLI 提交、验证和导出；人可在预览中审视，再修改源文档。未来可增加事件日志、笔刷模型、局部修订命令及 PNG/动画导出，但不破坏 SPP 0.1 的可读性。

## 里程碑

| 阶段 | 交付 | 验收 |
| --- | --- | --- |
| M0 立项 | 协议草案、示例、CLI 验证/渲染/回放 | 示例可运行，非法数据返回结构化错误 |
| M1 可编辑创作 | add/move/reorder stroke、undo、版本事件 | 不改写整张图即可局部迭代 |
| M2 笔触表现 | 压力、宽度曲线、纹理、遮挡 | 同一路径可产生可感知的不同笔触 |
| M3 Agent 协作 | 任务约束、候选计划、差异审阅 | Agent 提议与人类确认可追踪 |
| M4 工作台 | 分层画布、时间轴、对比视图 | UI 与 CLI 读取同一文档 |

## 风险与决策

- 旧原型的导入与测试目前不稳定，保持实验区，不把它当作协议首版的依赖。
- 函数曲线容易显得机械，后续要以真实笔刷动力学、局部手工调整补足。
- 大量采样点可能造成性能与安全风险，0.1 设定步数和表达式边界。
